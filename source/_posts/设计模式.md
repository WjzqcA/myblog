# 设计模式

根据用途，设计模式主要分为三大类，总共 23 种经典模式。

| **类别**       | **核心目标**                                 | **代表性模式**                                               |
| -------------- | -------------------------------------------- | ------------------------------------------------------------ |
| **创建型模式** | 负责对象的创建，隐藏创建细节，降低耦合       | 单例模式、简单工程模式、工厂模式、抽象工厂模式、建造者模式、原型模式 |
| **结构型模式** | 处理类或对象的组合，优化类结构，实现功能复用 | 代理模式、适配器模式、装饰器模式、外观模式、组合模式         |
| **行为型模式** | 描述对象间的交互与职责分配，优化算法和流程   | 观察者模式、策略模式、迭代器模式、命令模式、状态模式         |

在设计模式中接口不仅仅指代interface，而是**对象对外提供的功能规范**，也就是：
- 客户端能调用的方法
- 方法的签名（名字、参数、返回值）

所以即便是一个具体类，也有它的**接口**，只是没有用 interface 声明而已。

三种模式类别的含义：
1. 创建型模式：关注“**对象的创建方式**”，即如何更灵活、可扩展地创建对象。它们让系统**与具体类的实例化过程解耦**，从而更容易应对需求变化。（创建对象不直接 new，而是通过一个封装好的方式来创建。）
2. 结构型设计模式：关注“**类与对象之间如何组合**”来形成更大的结构。它们帮助我们把**复杂系统结构化**，让各个部分之间更加灵活、低耦合地协作。（通过组合对象来获得新功能，而不是通过继承）
3. 行为型设计模式：关注“**对象之间的交互与职责分配**”，即如何让多个对象协同工作以完成任务。（定义对象间的通信方式，解耦它们的交互逻辑。）

## 一、创建型设计模式

### 1.1单列模式

**核心思想**：确保一个类在整个应用中**只有一个实例**，并提供全局唯一的访问点。使用static可以约束实现单列模式

**适用场景**：工具类、配置管理器、线程池等（避免重复创建对象浪费资源）。

单列模式的实现方式：

1）饿汉式（线程安全，类加载时初始化）

```java
public class Singleton {
    private static final Singleton instance = new Singleton();//static修饰，类一加载就会实例化
    private Singleton() {}
    public static Singleton getInstance() {
        return instance;
    }
}
```

2）懒汉式（延迟加载，线程不安全）

```java
public class Singleton {
    private static Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if(instance == null) {
            instance = new Singleton();
        }
        return instance;
    }//只有第一次调用这个方法时才会new Singleton
}
```

### 1.2简单（静态）工厂模式

核心思想：由一个**工厂类**根据**传入的参数**决定创建哪一个具体产品实例。简单工程模式专门定义一个类来负责创建其他类的实例，被创建的实列通常都具有共同的父类。

```java
// 产品接口
interface Shape {
    void draw();
}
// 具体产品
class Circle implements Shape {
    public void draw() { System.out.println("画圆"); }
}
class Rectangle implements Shape {
    public void draw() { System.out.println("画矩形"); }
}
// 工厂类
class ShapeFactory {
    public static Shape createShape(String type) {
        if(type.equalsIgnoreCase("circle")) return new Circle();
        else if(type.equalsIgnoreCase("rectangle")) return new Rectangle();
        else return null;
    }
}
// 使用
Shape s = ShapeFactory.createShape("circle");
s.draw();
```

优点：简单，客户端只需知道工厂类即可创建对象 缺点：工厂类集中了所有产品逻辑，一旦增加新产品，需要修改工厂类（违反开闭原则）

### 1.3工厂模式

为了解决简单工程模式违背了开闭原则的问题

核心思想：定义一个用于创建对象的接口，让子类决定示例化哪个类。工厂方法使一个类的实例化延迟到其子类（将创建对象的职责交给子类）.

java

```java
// 产品接口
interface Shape { void draw(); }
// 具体产品
class Circle implements Shape { public void draw() { System.out.println("画圆"); } }
class Rectangle implements Shape { public void draw() { System.out.println("画矩形"); } }
// 工厂接口
interface ShapeFactory { Shape createShape(); }
// 具体工厂（如果还有新的只需要扩展子工程就好了）
class CircleFactory implements ShapeFactory {
    public Shape createShape() { return new Circle(); }
}
class RectangleFactory implements ShapeFactory {
    public Shape createShape() { return new Rectangle(); }
}
// 使用
ShapeFactory factory = new CircleFactory();//这里直接选择所要用到的子类进行实例化
Shape s = factory.createShape();
s.draw();
```

- 优点：遵循开闭原则，增加新产品只需增加新的工厂类，不修改已有代码
- 缺点：类数量增加，每个产品都需要对应一个工厂类

### 1.4抽象工厂模式

工程模式只能生产一个大类的产品

核心思想：提供一个**抽象工厂接口**，不同工厂生产不同产品族。面向产品族编程，而不是单个产品

java

```java
// 产品接口
interface Shape { void draw(); }
interface Color { void fill(); }
// 具体产品
class Circle implements Shape { public void draw() { System.out.println("画圆"); } }
class Rectangle implements Shape { public void draw() { System.out.println("画矩形"); } }
class Red implements Color { public void fill() { System.out.println("填充红色"); } }
class Blue implements Color { public void fill() { System.out.println("填充蓝色"); } }
// 抽象工厂 让工厂里面有两个大类的产品
interface AbstractFactory {
    Shape createShape();
    Color createColor();
}
// 具体工厂
class RedCircleFactory implements AbstractFactory {
    public Shape createShape() { return new Circle(); }
    public Color createColor() { return new Red(); }
}
class BlueRectangleFactory implements AbstractFactory {
    public Shape createShape() { return new Rectangle(); }
    public Color createColor() { return new Blue(); }
}
// 使用
AbstractFactory factory = new RedCircleFactory();
Shape s = factory.createShape();
Color c = factory.createColor();
s.draw();
c.fill();
```

- 优点：
  - 生成一族相关产品，保证产品之间的兼容性
  - 遵循开闭原则，增加新产品族只需增加新工厂
- 缺点：
  - 增加新产品（单个产品）比较麻烦，需要修改工厂接口。假设现在我们要增加一个新的产品类型，比如 **Texture**（纹理），那么抽象工厂以及所有的具体工厂都要修改

### 1.5生成器模式

核心思想：将一个复杂对象的构建过程**封装起来**，按步骤构建对象，最终返回完整对象。

主要用于解决**复杂对象的构建问题**，尤其是对象由多个部分组成、构建过程复杂或可选参数较多时，非常有用。

举个例子： 点一份汉堡套餐：

- 汉堡可以有不同配料（芝士、鸡蛋、生菜）
- 配饮料和薯条也可选
- 建造者模式就像**厨房的厨师**：按步骤组合食材
- 客户端只关心“我要一个汉堡套餐”，不关心具体怎么做

### 1.6原型模式

核心思想：通过复制（克隆）已有对象来创建新对象，而不是通过 new 来实例化。创建对象成本高可以创建一个，然后克隆它得到新的对象。

## 二、结构型设计模式

### 2.1装饰器模式

核心思想：在不修改原有类的前提下，动态地给对象增加新的功能，比继承更灵活

简单来讲就是将被扩展对象作为参数传入装饰器中就行功能扩展

一般包含四个角色：

| 角色                                | 作用                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| **Component（抽象组件）**           | 定义统一接口                                                 |
| **ConcreteComponent（具体组件）**   | 被装饰的原始对象                                             |
| **Decorator（抽象装饰类）**         | 持有一个 component 引用，并实现相同接口。可以减少多个具体装饰类重复编写相同代码。 |
| **ConcreteDecorator（具体装饰类）** | 在调用原对象方法前后，添加额外行为                           |

简单例子：

```java
// 原始功能：输出文本
interface Printer {
    void print();
}
// 具体实现类
class SimplePrinter implements Printer {
    public void print() {
        System.out.print("Hello");
    }
}
//装饰器类
class DecoratorPrinter implements Printer {
    private Printer printer; // 持有原始对象
    public DecoratorPrinter(Printer printer) {
        this.printer = printer;
    }
    public void print() {
        System.out.print("【装饰开始】");
        printer.print(); // 调用原来的功能
        System.out.print("【装饰结束】");
    }
}
public class Main {
    public static void main(String[] args) {
        new DecoratorPrinter(new SimplePrinter()).print();
    }
}
```

使用场景：

- Java I/O 流系统（最经典例子）：

```java
InputStream in = new BufferedInputStream(new FileInputStream("test.txt"));
```

- GUI 组件（添加边框、滚动条等）
- 日志框架（给输出加时间戳、颜色等
- Web 过滤器（Servlet Filter）

### 2.2适配器模式

核心思想：将一个类的接口变换成客户端所期待的另一种接口，从而使原本因接口不匹配而无法在一起工作的两个类能够在一起工作

问题背景：假设现在的系统已经统一使用了新的接口，对于一些旧的接口就不能直接使用了（因为要统一使用新接口，旧的参数名什么的都不一样），这时候就可以使用适配器模式让新接口可以调用旧的方法，使用统一。

简单例子：

```java
//旧类
class MP3Player {
    public void playMP3(String fileName) {
        System.out.println("播放MP3文件: " + fileName);
    }
}
//适配器
class MediaAdapter implements MediaPlayer {
    private MP3Player mp3Player;
    public MediaAdapter(MP3Player mp3Player) {
        this.mp3Player = mp3Player;
    }
    @Override
    public void play(String audioType, String fileName) {
        if (audioType.equalsIgnoreCase("mp3")) {
            mp3Player.playMP3(fileName);
        } else {
            System.out.println("不支持的格式: " + audioType);
        }
    }
}
//客户端
public class Main {
    public static void main(String[] args) {
        MediaPlayer player = new MediaAdapter(new MP3Player());
        player.play("mp3", "music.mp3");
        player.play("mp4", "video.mp4");
    }
}
```

- 系统需要复用一些**接口不兼容的旧类**
- 封装第三方库（API 不一致）
- 将新旧接口进行桥接（例如 Android 的兼容库）
- 数据转换器、协议适配器（JSON ↔ XML）

### 2.3观察者模式

核心思想：当一个对象的状态发生变化时，**所有依赖它的对象都会收到通知并自动更新**。

主要构成：

| 角色                               | 说明                                 |
| ---------------------------------- | ------------------------------------ |
| **Subject（主题/被观察者）**       | 保存观察者列表，状态变化时通知观察者 |
| **Observer（观察者）**             | 接口或抽象类，定义响应更新的方法     |
| **ConcreteSubject（具体主题）**    | 实现 Subject，状态改变时通知观察者   |
| **ConcreteObserver（具体观察者）** | 实现 Observer，实现更新逻辑          |

简单例子：

```java
//气象站（WeatherStation被观察者）检测到天气变化后，自动通知两个显示设备（PhoneDisplay、TVDisplay）
//观察者接口
interface Observer {
    void update(String weather);
}
//被观察者
class WeatherStation {
    private List<Observer> observers = new ArrayList<>();
    private String weather;
    public void addObserver(Observer o) {
        observers.add(o);
    }//增加观察者到列表
    public void setWeather(String weather) {
        this.weather = weather;
        notifyObservers();
    }
    private void notifyObservers() {
        for (Observer o : observers) {
            o.update(weather);
        }//对列表中的观察者进行通知
    }
}
//具体观察者
class PhoneDisplay implements Observer {
    public void update(String weather) {
        System.out.println("手机显示：天气更新为 " + weather);
    }
}
class TVDisplay implements Observer {
    public void update(String weather) {
        System.out.println("电视显示：天气更新为 " + weather);
    }
}
//客户端
public class Main {
    public static void main(String[] args) {
        WeatherStation station = new WeatherStation();
        station.addObserver(new PhoneDisplay());
        station.addObserver(new TVDisplay());
        station.setWeather("晴天 ☀️");
        station.setWeather("下雨 🌧️");
    }
}
```

使用场景：

- **事件处理系统**：GUI 事件监听、按钮点击、输入框变化
- **订阅/发布模式**：消息推送、新闻订阅
- **MVC 模式**：模型（Model）变化，自动更新视图（View）
- **实时数据更新**：股票行情、天气信息推送

### 2.4外观模式

核心思想：要求一个子系统的外部与其内部的通信必须通过一个统一的对象进行外观模式提供一个高层次的接口，使得子系统更易使用。

简单例子： 你去餐厅点菜，不需要亲自找厨师、采购、服务员； 你只需要跟“服务员”说一声： “我要一份牛排套餐” 🍽️ 服务员（Facade）就会去协调厨房（子系统）完成这件事。 ✅ 你只看到简单的接口（点菜），而复杂的过程都被隐藏起来了

```java
// 子系统类
class CPU {
    void start() { System.out.println("CPU 启动"); }
}
class Memory {
    void load() { System.out.println("内存加载"); }
}
class Disk {
    void read() { System.out.println("硬盘读取"); }
}
// 外观类
class ComputerFacade {
    private CPU cpu = new CPU();
    private Memory memory = new Memory();
    private Disk disk = new Disk();
    void start() {
        System.out.println("电脑启动中...");
        cpu.start();
        memory.load();
        disk.read();
        System.out.println("启动完成！");
    }
}
// 客户端
public class Main {
    public static void main(String[] args) {
        ComputerFacade computer = new ComputerFacade();
        computer.start(); // 只调用一个方法即可
    }
}
```

缺点：不符合开闭原则（修改外观需改源码）

### 2.5代理模式

核心思想：给某个对象提供一个“代理对象”，**由代理来控制对原对象的访问**。也就是说不直接访问目标对象，而是通过“中间人”来间接访问（核心点在于访问时要额外控制或保护）

举个例子： 假设你要请一位“大明星”拍广告， 但你不能直接联系他，必须通过他的经纪人（代理）安排。

- **真实对象（RealSubject）**：大明星
- **代理对象（Proxy）**：经纪人
- **客户端（Client）**：广告公司

java

```java
interface Star {
    void bookShow();
}
//真实对象
class RealStar implements Star {
    public void bookShow() {
        System.out.println("大明星签约并出演！");
    }
}
//代理对象
class ProxyStar implements Star {
    private RealStar realStar;
    public ProxyStar(RealStar realStar) {
        this.realStar = realStar;
    }
    public void bookShow() {
        System.out.println("经纪人：沟通档期、签合同...");
        realStar.bookShow(); // 真实对象执行核心业务
        System.out.println("经纪人：结算费用、宣传活动。");
    }
}
//客户端
public class Main {
    public static void main(String[] args) {
        RealStar realStar = new RealStar();
        ProxyStar proxy = new ProxyStar(realStar);
        proxy.bookShow();
    }
}
```

| 对比项             | 静态代理                                 | 动态代理                         |
| ------------------ | ---------------------------------------- | -------------------------------- |
| **代理类创建方式** | 由程序员**手动编写**                     | 运行时**由JVM自动生成**          |
| **代码数量**       | 每个真实对象都需要一个对应代理类（很多） | 一个代理类可代理**多个对象**     |
| **灵活性**         | ❌ 不灵活（修改目标要改代码）             | ✅ 非常灵活（运行时决定代理谁）   |
| **性能**           | 稍快（编译期生成）                       | 稍慢（运行时反射生成）           |
| **常用场景**       | 小型系统，简单逻辑                       | Spring AOP、RPC 框架、权限校验等 |

### 2.6享元模式

核心思想：通过**共享对象**来减少内存使用，避免创建大量相同或相似的对象（常用于优化性能）

举个例子： 比如：打印文档时，每个字母都要生成一个对象？ 那会非常浪费内存。 但实际上字母 “A” 的形状是固定的，不管出现在第几页、什么位置。 所以我们只需要：

- **共享字母形状（内部状态）**
- **区分字母的位置、大小（外部状态）**

🌟优点： ✅ 极大节省内存，特别是大量重复对象的场景 ✅ 减少对象创建开销，提高性能 ✅ 可以与工厂模式结合使用（享元工厂）

| 应用场景        | 示例                              |
| --------------- | --------------------------------- |
| 文本编辑器      | 字体、字形共享（A、B、C）         |
| 游戏对象        | 子弹、树木、粒子等大量重复对象    |
| 数据库连接池    | 连接对象的复用                    |
| 线程池          | 线程的复用                        |
| Java String     | String.intern() 实现字符串常量池  |
| Java 包装类缓存 | Integer.valueOf(127) 返回缓存对象 |

### 2.7组合模式

核心思想：将对象组合成树形结构，客户端可以以**同样的方式对待单个对象和组合对象**。主要用于 **将对象组合成树形结构以表示“整体-部分”层次**，并且让客户端对单个对象和组合对象**统一操作**。

例子：

- 文件系统：文件（叶子）和文件夹（组合）
- 组织架构：员工（叶子）和部门（组合）
- 图形绘制：圆、矩形（叶子）和组合图形（组合）

### 2.8桥接模式

主要思想：将抽象部分与实现部分**分离**，使它们可以**独立变化**。主要目的是**解耦抽象与实现，使它们可以独立变化**。

举个例子： 比如我们有：

- 抽象维度：**形状（Shape）**
- 实现维度：**颜色（Color）**

传统做法： 如果用继承，会有

text

```
红色圆形、蓝色圆形、红色方形、蓝色方形...
```

类会爆炸。

桥接模式做法： 让形状持有一个颜色接口引用，用组合代替继承：

text

```
Shape（抽象） → has a → Color（实现）
就是变成红色（原型）、蓝色（圆形）这种组合的方式
```

## 三、行为型设计模式

### 3.1状态模式

核心思想：允许一个对象在其内部状态改变时改变它的行为，对象看起来似乎修改了它的类。其别名为状态对象(Objects for States)。（随着状态的改变行为也会发生改变，**把状态抽象成类**）

简单的例子： 假设你有一个电灯，它有三种状态：

- 关灯（Off）
- 开灯（On）
- 变色灯（Color）

不同状态下按下按钮，行为不一样。

java

```java
//状态接口
interface State {
    void pressSwitch(Light light);
}
//具体状态类
class OffState implements State {
    public void pressSwitch(Light light) {
        System.out.println("灯亮了！");
        light.setState(new OnState());
    }
}
class OnState implements State {
    public void pressSwitch(Light light) {
        System.out.println("进入变色模式！");
        light.setState(new ColorState());
    }
}
class ColorState implements State {
    public void pressSwitch(Light light) {
        System.out.println("灯关闭了！");
        light.setState(new OffState());
    }
}
//定义持有当前状态的对象
class Light {
    private State state;
    public Light() {
        state = new OffState(); // 初始状态：关灯
    }
    public void setState(State state) {
        this.state = state;
    }
    public void pressSwitch() {
        state.pressSwitch(this);
    }
}
//客户端
public class Main {
    public static void main(String[] args) {
        Light light = new Light();
        light.pressSwitch(); // 灯亮了！
        light.pressSwitch(); // 进入变色模式！
        light.pressSwitch(); // 灯关闭了！
    }
}
```

优点：

- **避免大量 if-else/switch 判断**（比如状态机的那种嵌套逻辑）
- **新增状态时，只需添加一个新类**，不用修改原有代码

### 3.2策略模式

**核心思想：\**定义一系列算法（或行为），让它们可以互相替换，而不改变使用这些算法的代码，也称为政策模式\**（是行为型设计模式中最常用、也最实用的一个）**

举个例子： 比如你有一个“出行”类，你可以选择不同的出行策略：

- 走路（Walk）
- 开车（Drive）
- 坐地铁（Subway）

这些方式都能“出行”，但实现细节不一样。

java

```java
//定义策略接口
interface TravelStrategy {
    void travel();
}
//定义不同的具体策略
class WalkStrategy implements TravelStrategy {
    public void travel() {
        System.out.println("用双脚走路出行");
    }
}
class DriveStrategy implements TravelStrategy {
    public void travel() {
        System.out.println("开车出行");
    }
}
class SubwayStrategy implements TravelStrategy {
    public void travel() {
        System.out.println("坐地铁出行");
    }
}
//定义环境类（Context）-持有策略对象
class Traveler {
    private TravelStrategy strategy;
    // 可以动态设置出行策略
    public void setStrategy(TravelStrategy strategy) {
        this.strategy = strategy;
    }
    public void travel() {
        if (strategy == null) {
            System.out.println("请先选择出行方式！");
        } else {
            strategy.travel();
        }
    }
}
//客户端
public class Main {
    public static void main(String[] args) {
        Traveler traveler = new Traveler();
        traveler.setStrategy(new WalkStrategy());
        traveler.travel(); // 用双脚走路出行
        traveler.setStrategy(new DriveStrategy());
        traveler.travel(); // 开车出行
        traveler.setStrategy(new SubwayStrategy());
        traveler.travel(); // 坐地铁出行
    }
}
```

- **消除了 if-else 或 switch**

  （不再用一堆条件判断出行方式）

- **新增策略不用改原代码**，只需实现新类即可

- **策略可自由切换、复用性强**

### 3.3责任链模式

核心思想：让多个对象有机会处理同一个请求，形成一条“链”。请求沿着链传递，直到有对象处理它为止。

举个例子： 假设你在公司请假：

- 请假 1 天 → 组长批
- 请假 3 天 → 经理批
- 请假 7 天 → 总监批

请求会一层层往上交，如果当前层不能处理，就交给下一个人。 👉 这就是“责任链”。

java

```java
//抽象处理者
abstract class Handler {
    protected Handler next; // 下一个处理者
    public void setNext(Handler next) {
        this.next = next;
    }
    public abstract void handleRequest(int days);
}
//具体处理者
class Leader extends Handler {
    public void handleRequest(int days) {
        if (days <= 1) {
            System.out.println("组长批准了 " + days + " 天假");
        } else if (next != null) {
            next.handleRequest(days);
        }
    }
}
class Manager extends Handler {
    public void handleRequest(int days) {
        if (days <= 3) {
            System.out.println("经理批准了 " + days + " 天假");
        } else if (next != null) {
            next.handleRequest(days);
        }
    }
}
class Director extends Handler {
    public void handleRequest(int days) {
        if (days <= 7) {
            System.out.println("总监批准了 " + days + " 天假");
        } else {
            System.out.println("超出审批权限，无法批准");
        }
    }
}
//客户端
public class Main {
    public static void main(String[] args) {
        Handler leader = new Leader();
        Handler manager = new Manager();
        Handler director = new Director();
        // 组装责任链
        leader.setNext(manager);
        manager.setNext(director);
        // 测试
        leader.handleRequest(1);
        leader.handleRequest(3);
        leader.handleRequest(7);
        leader.handleRequest(10);
    }
}
```

常见应用：

- Java Web 的 **Filter 链**（Servlet Filter）
- **Spring MVC Interceptor**
- **Netty Pipeline**
- 日志系统（不同级别过滤）

### 3.4模板方法模式

在父类中定义算法的**骨架（流程模板）**，把某些步骤延迟到子类中去实现，让子类在不改变整体流程的前提下，**重定义某些具体步骤**。（固定步骤父类，可变化的交给子类）

举个例子： 比如你每天上班的流程： 起床 → 洗漱 → 吃早餐 → 去公司 → 工作 这个流程每天都一样（模板）， 但“吃早餐”这一步，每个人不一样（子类实现）

**Hook method（钩子方法）：钩子方法（Hook Method）** 是模板方法模式中定义的一个 **可选的、由子类决定是否覆盖或触发的“挂钩点”**。

模板方法的骨架一般长这样：

java

```java
public final void templateMethod() {
    step1();
    step2();
    if (hook()) { // 钩子方法
        step3();
    }
    step4();
}
// 钩子方法，子类可以改写
protected boolean needCaptcha() { return true; }
//如果子类需要可以默认，如果不需要步骤3那么可以重写改成false
```

优点：

- 封装不变部分，扩展可变部分
- 避免重复代码，提高复用性
- 便于维护（统一算法骨架）

缺点： 子类过多时，难以维护 父类对子类有强约束，可能导致“继承僵化”问题

| 应用场景 | 示例                                 |
| -------- | ------------------------------------ |
| 框架设计 | Spring 的 JdbcTemplate、RestTemplate |
| Web 模板 | Servlet 的 doGet/doPost              |
| 构建流程 | 报表生成、任务调度、算法模板         |
| 游戏逻辑 | 固定流程（如战斗回合、关卡流程）     |

### 3.5命令模式

核心思想：将一个**请求封装成一个对象**，从而让你可用不同的请求、队列或日志来参数化客户端，支持撤销操作。**命令对象封装了请求的动作**，可放入队列、撤销或组合成宏命令。

举个例子： 假设你在家里用遥控器控制电器：

- **遥控器（Invoker）**：按下按钮就执行命令
- **电灯（Receiver）**：真正执行开/关操作
- **开灯命令（Command）**：封装请求的对象

这样遥控器不用知道具体灯怎么开，只管调用命令即可。

### 3.6备忘录模式

核心思想：在不破坏封装性的前提下，捕获对象内部状态，并在需要时恢复它（主要用于**保存对象状态，以便在以后恢复**，典型应用就是 **撤销/重做功能**。）

通俗点说：

- 对象的状态随操作改变
- 你想在某个时间点保存状态
- 以后可以回到这个状态（撤销、恢复）
- 不暴露对象内部实现细节

### 3.7迭代器模式

核心思想：提供一种**统一的方法**访问集合对象的元素，而无需暴露集合内部结构。

### 3.8行为型设计模式

核心思想：用于**减少对象之间的复杂依赖关系**，通过一个中介者对象来统一管理和协调多个对象之间的交互。

举个例子： 想象你在一个群聊中：

- 以前每个人都要单独私聊别人（复杂且容易混乱）。
- 现在有一个群（中介者），所有人都把消息发到群里，由群统一广播。 这个群就是“中介者”。

### 3.9访问者模式

核心思想：是一种将**数据结构**与**对其操作**分离的设计模式。它让你在**不修改原有类结构**的情况下， **增加新的操作（访问逻辑）**。

举个例子： 假设你去参观一个博物馆（Museum）。

- 博物馆里有不同类型的展品（比如：绘画、雕塑、古籍）。
- 你是**访问者（Visitor）**，
- 你对不同的展品会有不同的行为（拍照、研究、记录）。

👉 展品类不需要知道访问者要干什么，访问者自己决定。 这样就能在不改动展品类的情况下，扩展新的“访问逻辑”。

### 3.10解释器模式

核心思想：是用来**定义一种语言的文法表示**，并建立一个**解释器**来解释这套语言中的句子。

举个例子： 比如你要设计一个简单的“计算器”： 输入：2 + 3 - 1 输出：4 你可以：

- 定义规则（“+” 表示加，“-” 表示减）
- 写解释器去**理解和执行**这些规则。

解释器模式的目的，就是把这种“规则 + 执行逻辑”封装起来
